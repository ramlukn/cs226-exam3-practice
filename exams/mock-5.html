Q12.5 pts

Quicksort with Lomuto partition always uses a[hi] as the pivot. (a) Explain why it takes O(n²) on an array that is already sorted. (b) Explain what median-of-three pivot selection changes for that input. (c) Give one input on which median-of-three Lomuto quicksort is still O(n²), and say why.

The rubric unlocks when you submit.

Rubric and reference solution

2.5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +1(a) On sorted input a[hi] is the largest value, so partition puts every other element on one side: subproblems of size n−1, n−2, …, which sums to about n²/2 comparisons
  • +1(b) The median of first, middle and last of a sorted range is its true middle value, so each partition splits the range roughly in half: O(n log n)
  • +0.5(c) An array where every value is equal: Lomuto sends everything that isn't strictly smaller to one side, so every split is still n−1 and 0, whatever the pivot
  • −0.125Gives the right complexity without the reason (which side the elements go to, or how the subproblem sizes add up)

(a) Sorted input, pivot = max: the left part has n−1 elements, the right part none. The total work is (n−1) + (n−2) + … + 1 = O(n²). (b) Median-of-three picks the middle value of a sorted range, so both halves have about n/2 elements: depth log n, O(n log n). (c) All-equal values (e.g. [4, 4, 4, 4, 4]): no element is < the pivot, so every partition is maximally lopsided again.

Q22.5 pts

You are given an unsorted array of n values and want to turn it into a min-heap in place. (a) Bottom-up heapify calls sink on some of the indices. Which indices, in what order, and why does it skip the others? (b) Why is bottom-up heapify O(n), while inserting the n values one at a time (each with swim) is O(n log n)?

The rubric unlocks when you submit.

Rubric and reference solution

2.5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.75(a) Sinks indices from n/2 − 1 down to 0: the last internal node first, the root last
  • +0.5(a) Skips n/2 … n−1 because those are leaves: a single node is already a valid heap, so there is nothing to sink
  • +0.75(b) Heapify is O(n): about half the nodes are leaves and do no work, a quarter sink at most 1 level, an eighth at most 2, … and that sum is bounded by n
  • +0.5(b) Inserting one at a time is O(n log n): later inserts land at the bottom of a tree of height log n and may swim all the way up
  • −0.125Gives the right order or bound without the reason

(a) for (int i = n / 2 - 1; i >= 0; i--) sink(i);. Going from the bottom up means that when sink(i) runs, both of i's subtrees are already heaps, which is exactly what sink needs. (b) The cost of sinking a node is its height, and most nodes are near the bottom: n/4·1 + n/8·2 + n/16·3 + … ≤ n. Swim's cost is a node's depth, and most nodes are deep, so n inserts cost up to n·log n.

public T remove() {
  if (size == 0) throw new NoSuchElementException();
  T best = heap[0];               // save before overwriting
  heap[0] = heap[size - 1];       // last value moves to the root
  heap[size - 1] = null;          // no stale reference left behind
  size--;
  if (size > 0) sink(0);          // restore order from the top
  return best;
}

  • +0.25Throws IllegalArgumentException for a null key
  • +0.5Finds the bucket with Math.floorMod(key.hashCode(), buckets.length)
  • +0.5Walks the chain with two pointers (previous and current), advancing both
  • +0.5Compares keys with equals
  • +0.75Removing the head: buckets[i] = curr.next
  • +0.75Removing later in the chain: prev.next = curr.next
  • +0.25Decrements size
  • +0.5Returns the removed value, or null after the loop
  • −0.75Solution is recursive
  • −0.5Searches every bucket
  • −0.25Compares keys with ==
  • −0.125Minor logic or major syntax errors showing lack of understanding
public V remove(K key) {
  if (key == null) throw new IllegalArgumentException();
  int i = Math.floorMod(key.hashCode(), buckets.length);
  Node<K, V> prev = null;
  Node<K, V> curr = buckets[i];
  while (curr != null) {
    if (curr.key.equals(key)) {
      if (prev == null) buckets[i] = curr.next;   // removing the head
      else prev.next = curr.next;                 // removing from the middle or end
      size--;
      return curr.value;
    }
    prev = curr;                                  // move BOTH pointers
    curr = curr.next;
  }
  return null;
}

The head case is separate because no node points to the head: the bucket array does. Forgetting it is the most common bug here. A one-node chain is also a head removal.

  • +0.5Does nothing unless used > slots.length / 2 (with real, not integer, division)
  • +0.5Grows only when size > slots.length / 2 too
  • +0.5Picks the next prime by advancing primeIndex, and 2m + 1 past the end of the list
  • +0.5Otherwise rehashes at the same size

  • +0.75Computes each entry's home slot with the new length (call indexFor after replacing slots)
  • +0.75Linear-probes in the new table until an empty slot, with % slots.length
  • +0.75Resets used to 0 and counts each reinserted entry (so used == size afterwards)
  • +0.5Leaves size unchanged

private void rehashIfNeeded() {
  if (used <= slots.length / 2.0) return;            // still under the limit
  if (size > slots.length / 2.0) {                   // really full: grow
    int capacity = (primeIndex + 1 < PRIMES.length)
        ? PRIMES[++primeIndex]
        : 2 * slots.length + 1;
    rehash(capacity);
  } else {
    rehash(slots.length);                            // mostly tombstones: same size
  }
}

@SuppressWarnings("unchecked")
private void rehash(int capacity) {
  Entry<K, V>[] old = slots;
  slots = (Entry<K, V>[]) new Entry[capacity];       // indexFor now uses the new length
  used = 0;
  for (Entry<K, V> e : old) {                        // old-slot order
    if (e == null || e.deleted) continue;            // tombstones are dropped
    int i = indexFor(e.key);
    while (slots[i] != null) i = (i + 1) % slots.length;   // new table has no tombstones
    slots[i] = e;
    used++;
  }                                                  // size is unchanged; now used == size
}

The new table has no tombstones, so the reinsert loop only needs to look for null. Reusing put inside rehash also works if it doesn't double-count size or trigger another rehash.

  • +0.5Returns true for a graph with no vertices
  • +0.5Starts from any one vertex (e.g. the first from vertices())
  • +0.5Uses a visited set and a queue, marking and enqueueing the start
  • +1BFS loop: dequeue, iterate g.neighbors(v), mark and enqueue each unvisited neighbor
  • +1Returns whether the number of visited vertices equals numVertices()
  • +0.5Runs a single search, not one per vertex (O(V + E))

public static <V> boolean isConnected(Graph<V> g) {
  if (g.numVertices() == 0) return true;
  V start = g.vertices().iterator().next();   // any vertex works
  Set<V> visited = new HashSet<>();
  Queue<V> queue = new ArrayDeque<>();
  visited.add(start);
  queue.add(start);
  while (!queue.isEmpty()) {
    V v = queue.remove();
    for (V w : g.neighbors(v)) {
      if (!visited.contains(w)) {
        visited.add(w);
        queue.add(w);
      }
    }
  }
  return visited.size() == g.numVertices();   // reached everyone?
}

In an undirected graph, if one vertex reaches all the others, then every pair is connected through it, so one search is enough.

public void insert(T item, P priority) {
  if (item == null || priority == null) throw new IllegalArgumentException();
  if (index.containsKey(item)) throw new IllegalArgumentException();   // items are unique
  if (size == heap.length) heap = Arrays.copyOf(heap, 2 * heap.length);
  heap[size] = new Entry<>(item, priority);
  index.put(item, size);          // record the slot BEFORE swimming
  size++;
  swim(size - 1);
}

public T removeBest() {
  if (size == 0) throw new NoSuchElementException();
  T best = heap[0].item;
  swap(0, size - 1);              // best moves to the end; swap updates the map
  index.remove(best);
  heap[size - 1] = null;
  size--;
  if (size > 0) sink(0);
  return best;
}

  • +0.25Throws IllegalArgumentException when k < 0 or k ≥ a.length
  • +0.5Starts with lo = 0, hi = a.length - 1 and loops
  • +0.5Partitions the current range and gets the pivot's index p
  • +0.75Returns a[p] when p == k
  • +0.75Continues in only one side: hi = p - 1 when k < p, otherwise lo = p + 1
  • +0.25Keeps k as an index into the whole array (doesn't shift it)
  • −0.75Solution is recursive
  • −0.5Sorts the whole array (or recurses into both sides) instead of selecting
  • −0.125Minor logic or major syntax errors showing lack of understanding
public static int kthSmallest(int[] a, int k) {
  if (k < 0 || k >= a.length) throw new IllegalArgumentException();
  int lo = 0, hi = a.length - 1;
  while (true) {
    int p = partition(a, lo, hi);     // a[p] is in its final sorted place
    if (p == k) return a[p];
    if (k < p) hi = p - 1;            // answer is left of the pivot
    else lo = p + 1;                  // answer is right of the pivot
  }
}

After partition, a[p] is exactly where it would be in the sorted array, so p tells you which side k is on. Expected O(n); worst case O(n²) like quicksort.

  • +1Adds a neighbor only if unvisited, and marks it when it is first added (so it appears once)
  • +0.5Iterates over g.neighbors(v)
  • +0.75Stops when a level comes out empty and doesn't add the empty level
  • +0.75Returns the levels in order of distance
  • −1Uses DFS (a stack or recursion) to assign levels: a vertex can be given a distance longer than the shortest

public static <V> List<List<V>> levels(Graph<V> g, V start) {
  List<List<V>> result = new ArrayList<>();
  Set<V> visited = new HashSet<>();
  List<V> current = new ArrayList<>();
  visited.add(start);
  current.add(start);
  while (!current.isEmpty()) {
    result.add(current);                      // every vertex at this distance
    List<V> next = new ArrayList<>();
    for (V v : current) {
      for (V w : g.neighbors(v)) {
        if (!visited.contains(w)) {           // check AND mark when first seen
          visited.add(w);
          next.add(w);
        }
      }
    }
    current = next;                           // one level further out
  }
  return result;
}

Two equivalent designs: process a whole level at a time (the reference), or run normal BFS with a Map<V, Integer> of distances and append each dequeued vertex to result.get(dist), adding a new list when dist reaches the current size.
