Q22.5 pts

Undirected graph with edges A–B, A–C, B–D, C–D. (a) A student's BFS from A marks a vertex visited when it is dequeued, not when it is enqueued, and skips a dequeued vertex that's already visited. Which vertex gets enqueued twice, and from where? (b) Does that BFS still find correct fewest-edge distances? What does the mistake cost? (c) Why can't DFS find fewest-edge distances? Give a small graph and a DFS order where it gets one wrong.

The rubric unlocks when you submit.

Rubric and reference solution

2.5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.75(a) D: enqueued once from B and again from C, because neither saw it marked
  • +0.75(b) The distances are still right (the first copy of D dequeued has the smallest distance, the second is skipped), but the queue can hold duplicates: up to O(E) entries instead of O(V), and extra work
  • +1(c) DFS goes deep along one path, so it can reach a vertex by a long path first. Example: triangle A–B, B–C, A–C; DFS from A visits B then C through B, giving C distance 2, but the edge A–C makes it 1
  • −0.125Says DFS is wrong without an example or a reason

(a) Dequeue A, enqueue B and C (unmarked). Dequeue B, mark it, enqueue D. Dequeue C, mark it, D is still unmarked, so enqueue D again. (b) Correct distances, because BFS still dequeues in distance order and the second D is skipped. Cost: duplicate queue entries, up to one per edge. (c) DFS records the distance along the path it happens to take, which is not always the shortest one. BFS explores in rings of increasing distance, so its first visit is by a shortest path.

Write a key iterator for the separate-chaining HashMap that visits the buckets in reverse order: bucket m - 1 first, down to bucket 0. Within a bucket, walk the chain from head to tail. Use O(1) extra space; a full iteration takes O(n + m). hasNext must not change anything, and next() throws NoSuchElementException when no keys are left.

Rubric and reference solution

4 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Fields: the current node and the next bucket to look at, starting at buckets.length - 1
  • +0.75The constructor moves to the first key, skipping empty buckets
  • +0.5hasNext returns curr != null, with no side effects
  • +0.75next returns the current node's key
  • +0.5Moves along the chain with curr.next
  • +0.75When a chain ends, loops down to the next non-empty bucket, stopping below 0
  • +0.25Throws NoSuchElementException when no keys are left
  • −0.5Copies the keys into a list or array first (O(n) space)
  • −0.5Visits buckets from 0 upward instead of in reverse
  • −0.125Minor logic or major syntax errors showing lack of understanding
private class ReverseKeyIterator implements Iterator<K> {
  private Node<K, V> curr;                 // node next() returns; null means done
  private int slot = buckets.length - 1;   // next bucket to examine, counting DOWN

  ReverseKeyIterator() {
    advance();                             // land on the first key
  }

  private void advance() {
    if (curr != null) curr = curr.next;    // same chain: step along it
    while (curr == null && slot >= 0) {    // chain over: find the next non-empty bucket below
      curr = buckets[slot];
      slot--;
    }
  }

  @Override
  public boolean hasNext() {
    return curr != null;
  }

  @Override
  public K next() {
    if (!hasNext()) throw new NoSuchElementException();
    K key = curr.key;
    advance();
    return key;
  }
}

Identical to the usual key iterator except the bucket index starts at buckets.length - 1, counts down, and stops at slot >= 0. Writing advance() once and calling it from both the constructor and next covers every case.

public V put(K key, V value) {
  if (key == null || value == null) throw new IllegalArgumentException();
  int i = indexFor(key);
  int firstTombstone = -1;
  while (slots[i] != null) {                       // only an empty slot ends the search
    if (slots[i].deleted) {
      if (firstTombstone == -1) firstTombstone = i; // remember the first one, keep going
    } else if (slots[i].key.equals(key)) {
      V old = slots[i].value;                      // key already here: replace
      slots[i].value = value;
      return old;
    }
    i = (i + 1) % slots.length;
  }
  if (firstTombstone != -1) {
    i = firstTombstone;                            // reuse it: used stays the same
  } else {
    used++;                                        // filling an empty slot
  }
  slots[i] = new Entry<>(key, value);
  size++;
  rehashIfNeeded();                                // after the new key is stored
  return null;
}

public ArrayHeap(T[] items) {
  if (items == null) throw new IllegalArgumentException();
  heap = Arrays.copyOf(items, Math.max(1, items.length));   // copy: don't change the caller's array
  size = items.length;
  for (int i = size / 2 - 1; i >= 0; i--) {                 // last internal node up to the root
    sink(i);
  }
}

Indices from size / 2 on are leaves, which are already heaps, so the loop starts at the last internal node. An empty array gives size / 2 - 1 = -1, so the loop doesn't run at all.

  • +1Seeds it with the first value of every non-empty row, along with which row and position it came from
  • +0.5Loops while the queue is not empty
  • +0.75Removes the smallest entry and appends its value to the result
  • +1Adds the next value from the same row (if there is one)
  • +0.5Skips empty rows without crashing
  • +0.75Never holds more than one entry per row, so the queue size stays ≤ k
  • −1Puts all n values into the queue at once (O(n log n), queue of size n)

public static List<Integer> mergeSorted(int[][] lists) {
  List<Integer> out = new ArrayList<>();
  // each entry is {value, which list, position in that list}, smallest value first
  PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> Integer.compare(x[0], y[0]));
  for (int r = 0; r < lists.length; r++) {
    if (lists[r].length > 0) pq.add(new int[]{lists[r][0], r, 0});   // first of every non-empty list
  }
  while (!pq.isEmpty()) {
    int[] e = pq.remove();                      // the smallest remaining value overall
    out.add(e[0]);
    int r = e[1], next = e[2] + 1;
    if (next < lists[r].length) {
      pq.add(new int[]{lists[r][next], r, next});   // replace it with the next one from the same list
    }
  }
  return out;
}

Each value enters and leaves the queue once, and the queue holds at most k entries, so each operation is O(log k): O(n log k) in total. Storing the row and position with the value is what lets you find "the next one from the same row".

  • +0.5Scans j from lo up to hi - 1

  • +0.5After the loop, swaps the pivot from hi to the boundary

private static int partition(int[] a, int lo, int hi) {
  int pivot = a[hi];
  int i = lo;                        // a[lo..i-1] < pivot
  for (int j = lo; j < hi; j++) {    // a[i..j-1] >= pivot
    if (a[j] < pivot) {
      swap(a, i, j);
      i++;
    }
  }
  swap(a, i, hi);                    // pivot goes between the two regions
  return i;
}

Label every vertex of an undirected graph with the number of its connected component: the first component found is 0, the next 1, and so on. Return a map from each vertex to its label. Use BFS, don't modify the graph, and put each vertex in a queue at most once.

Rubric and reference solution

5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Creates the result map (which can double as the visited set) and a component counter starting at 0
  • +0.75Loops over every vertex and starts a BFS only from vertices that have no label yet
  • +0.5Labels the start vertex and enqueues it
  • +1BFS: dequeue, iterate g.neighbors(v), label and enqueue each unlabeled neighbor with the same counter value
  • +0.75Increments the counter once per component, after its BFS finishes
  • +0.75Every vertex ends up labeled, including isolated vertices with no edges
  • +0.75Total work O(V + E): each vertex is enqueued once over the whole method
  • −0.5Increments the counter inside the BFS (per vertex) instead of per component
  • −0.5Modifies the graph
  • −0.125Minor logic or major syntax errors showing lack of understanding
public static <V> Map<V, Integer> componentIds(Graph<V> g) {
  Map<V, Integer> id = new HashMap<>();        // also the visited set
  int next = 0;
  for (V s : g.vertices()) {
    if (id.containsKey(s)) continue;           // already in a component we found
    id.put(s, next);                           // s starts a new component
    Queue<V> queue = new ArrayDeque<>();
    queue.add(s);
    while (!queue.isEmpty()) {
      V v = queue.remove();
      for (V w : g.neighbors(v)) {
        if (!id.containsKey(w)) {              // check AND mark before enqueueing
          id.put(w, next);
          queue.add(w);
        }
      }
    }
    next++;                                    // only after the whole component is labeled
  }
  return id;
}
