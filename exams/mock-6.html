Write a key iterator for the separate-chaining HashMap that visits the buckets in reverse order: bucket m - 1 first, down to bucket 0. Within a bucket, walk the chain from head to tail. Rubric and reference solution

4 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Fields: the current node and the next bucket to look at, starting at buckets.length - 1
  • +0.75The constructor moves to the first key, skipping empty buckets
  • +0.5hasNext returns curr != null, with no side effects
  • +0.75next returns the current node's key
  • +0.5Moves along the chain with curr.next
  • +0.75When a chain ends, loops down to the next non-empty bucket, stopping below 0
  • +0.25Throws NoSuchElementException when no keys are left
  • −0.5Copies the keys into a list or array first (O(n) space)
  • −0.5Visits buckets from 0 upward instead of in reverse
  • −0.125Minor logic or major syntax errors showing lack of understanding
private class ReverseKeyIterator implements Iterator<K> {
  private Node<K, V> curr;                 // node next() returns; null means done
  private int slot = buckets.length - 1;   // next bucket to examine, counting DOWN

  ReverseKeyIterator() {
    advance();                             // land on the first key
  }

  private void advance() {
    if (curr != null) curr = curr.next;    // same chain: step along it
    while (curr == null && slot >= 0) {    // chain over: find the next non-empty bucket below
      curr = buckets[slot];
      slot--;
    }
  }

  @Override
  public boolean hasNext() {
    return curr != null;
  }

  @Override
  public K next() {
    if (!hasNext()) throw new NoSuchElementException();
    K key = curr.key;
    advance();
    return key;
  }
}

Identical to the usual key iterator except the bucket index starts at buckets.length - 1, counts down, and stops at slot >= 0. Writing advance() once and calling it from both the constructor and next covers every case.

public V put(K key, V value) {
  if (key == null || value == null) throw new IllegalArgumentException();
  int i = indexFor(key);
  int firstTombstone = -1;
  while (slots[i] != null) {                       // only an empty slot ends the search
    if (slots[i].deleted) {
      if (firstTombstone == -1) firstTombstone = i; // remember the first one, keep going
    } else if (slots[i].key.equals(key)) {
      V old = slots[i].value;                      // key already here: replace
      slots[i].value = value;
      return old;
    }
    i = (i + 1) % slots.length;
  }
  if (firstTombstone != -1) {
    i = firstTombstone;                            // reuse it: used stays the same
  } else {
    used++;                                        // filling an empty slot
  }
  slots[i] = new Entry<>(key, value);
  size++;
  rehashIfNeeded();                                // after the new key is stored
  return null;
}

public ArrayHeap(T[] items) {
  if (items == null) throw new IllegalArgumentException();
  heap = Arrays.copyOf(items, Math.max(1, items.length));   // copy: don't change the caller's array
  size = items.length;
  for (int i = size / 2 - 1; i >= 0; i--) {                 // last internal node up to the root
    sink(i);
  }
}

Indices from size / 2 on are leaves, which are already heaps, so the loop starts at the last internal node. An empty array gives size / 2 - 1 = -1, so the loop doesn't run at all.

Each row of lists is sorted in ascending order. Return all their values in one ascending list. With k rows and n values in total, it must run in O(n log k): use a java.util.PriorityQueue that never holds more than k entries. Rows may be empty.

5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Creates a PriorityQueue ordered by value (e.g. a comparator on int[]{value, row, index})
  • +1Seeds it with the first value of every non-empty row, along with which row and position it came from
  • +0.5Loops while the queue is not empty
  • +0.75Removes the smallest entry and appends its value to the result
  • +1Adds the next value from the same row (if there is one)
  • +0.5Skips empty rows without crashing
  • +0.75Never holds more than one entry per row, so the queue size stays ≤ k
  • −1Puts all n values into the queue at once (O(n log n), queue of size n)
  • −0.5Concatenates and sorts instead of merging
  • −0.125Minor logic or major syntax errors showing lack of understanding
public static List<Integer> mergeSorted(int[][] lists) {
  List<Integer> out = new ArrayList<>();
  // each entry is {value, which list, position in that list}, smallest value first
  PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> Integer.compare(x[0], y[0]));
  for (int r = 0; r < lists.length; r++) {
    if (lists[r].length > 0) pq.add(new int[]{lists[r][0], r, 0});   // first of every non-empty list
  }
  while (!pq.isEmpty()) {
    int[] e = pq.remove();                      // the smallest remaining value overall
    out.add(e[0]);
    int r = e[1], next = e[2] + 1;
    if (next < lists[r].length) {
      pq.add(new int[]{lists[r][next], r, next});   // replace it with the next one from the same list
    }
  }
  return out;
}

Each value enters and leaves the queue once, and the queue holds at most k entries, so each operation is O(log k): O(n log k) in total. Storing the row and position with the value is what lets you find "the next one from the same row".

  • +0.5Throws IndexOutOfBoundsException when index < 0 or index >= size (not data.length)
  • +0.5Saves the value at index before it is overwritten
  • +0.75Shifts data[i] = data[i + 1] for i from index up to size - 2, left to right
  • +0.5Sets the old last slot data[size - 1] to null
  • +0.5Decrements size
  • +0.25Returns the saved value
  • −0.5Shifts right to left (or in the wrong direction), overwriting values before they are moved
  • −0.25Copies into a new array on every remove (O(n) extra space each time)
  • −0.125Minor logic or major syntax errors showing lack of understanding
public T remove(int index) {
  if (index < 0 || index >= size) throw new IndexOutOfBoundsException();
  T removed = data[index];                 // save before it's overwritten
  for (int i = index; i < size - 1; i++) {
    data[i] = data[i + 1];                 // shift everything after it one left
  }
  data[size - 1] = null;                   // no stale reference at the old end
  size--;
  return removed;
}

The shift has to go left to right: each slot is overwritten by its right neighbor, which hasn't been touched yet. The loop stops at size - 2 because slot size - 1 has no right neighbor; it gets set to null instead. O(n) worst case (removing index 0).

Finish the AVL tree's balancing code: updateHeight, rotateRight and rebalance. Rubric and reference solution

5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.25updateHeight: 1 + max(height(left), height(right)), using the null-safe height
  • +0.25rotateRight takes child = n.left
  • +0.5Moves child's right subtree under n: n.left = child.right
  • +0.5Puts n under child: child.right = n
  • +0.75Updates n's height before child's (child's height depends on n's)
  • +0.5Returns child, the new root of the subtree
  • +0.5rebalance computes the balance factor height(n.left) - height(n.right)
  • +0.75Left-heavy (> 1) and the left child leans right: first n.left = rotateLeft(n.left)
  • +0.5Left-heavy: then returns rotateRight(n)
  • +0.5Right-heavy (< -1): the mirror image, with n.right = rotateRight(n.right) when the right child leans left, then rotateLeft(n); returns n unchanged when balanced
  • −0.5Doesn't use a returned root (e.g. calls rotateLeft(n.left) without assigning it to n.left)
  • −0.25Reads n.left.height directly, which crashes when a child is null
  • −0.125Minor logic or major syntax errors showing lack of understanding
private void updateHeight(Node n) {
  n.height = 1 + Math.max(height(n.left), height(n.right));
}

private Node rotateRight(Node n) {
  Node child = n.left;
  n.left = child.right;      // child's right subtree moves under n
  child.right = n;           // n becomes child's right child
  updateHeight(n);           // n is now lower: fix it first
  updateHeight(child);       // child's height depends on n's
  return child;              // the new root of this subtree
}

private Node rebalance(Node n) {
  int balance = height(n.left) - height(n.right);
  if (balance > 1) {                               // left-heavy
    if (height(n.left.left) < height(n.left.right)) {
      n.left = rotateLeft(n.left);                 // left-right case: straighten it first
    }
    return rotateRight(n);
  }
  if (balance < -1) {                              // right-heavy (mirror image)
    if (height(n.right.right) < height(n.right.left)) {
      n.right = rotateRight(n.right);              // right-left case
    }
    return rotateLeft(n);
  }
  return n;                                        // already balanced
}

Picture for rotateRight: n has left child c, and c has right subtree T. After the rotation c is on top, n is c's right child, and T (whose keys are between c and n) becomes n's left subtree. Only n and c change height, and n is now the lower one, so update it first.
