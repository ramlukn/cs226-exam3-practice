Q12.5 pts

Person has fields String name, int age and long id. Its equals returns true when name and age are equal; it ignores id. For each hashCode below, say whether it obeys the hashCode contract, and if it does, whether it is a good choice for our HashMap. One sentence each.

  1. return age;
  2. return Objects.hash(name, age, id);
  3. return 0;
  4. return (int) (Math.random() * 1000);
  5. return Objects.hash(name, age);

The rubric unlocks when you submit.

Rubric and reference solution

2.5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5(a) Legal: equal Persons have equal ages. Weak: everyone with the same age collides, so buckets get long
  • +0.5(b) Illegal: two equal Persons with different ids get different hash codes, so lookups miss
  • +0.5(c) Legal but terrible: every key lands in one bucket, so get and put become O(n)
  • +0.5(d) Illegal: not consistent, the same object gives a different hash each call, so even the stored object can't be found
  • +0.5(e) Legal and good: uses exactly the fields equals uses and spreads keys out
  • −0.125Right verdict with no reason or a wrong reason. Award the item, then apply this penalty once

The test for legal is one question: can two objects that are equals ever get different hash codes? (b) can, through id; (d) can, even for one object. The test for good is how well unequal keys spread out: (c) puts everything in one bucket, (a) groups by age, (e) mixes both fields. Rule of thumb: hash exactly the fields equals compares.

Q22.5 pts

In an indexed min-heap, a student's swap(i, j) exchanges the two entries but only runs index.put(heap[i].item, i); it never updates the map for the entry that moved to j.

(a) Starting from empty, give a short sequence of operations after which changePriority changes the wrong item's priority, and say which item it changes.

(b) What is the running time of changePriority with a correct map, and what would it be if the heap had no map at all?

(c) When the new priority is smaller than the old one, why is swim enough, with no sink?

The rubric unlocks when you submit.

Rubric and reference solution

2.5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5(a) Explains the cause: the item that moved to j keeps its old slot number in the map
  • +0.75(a) A concrete sequence that shows it, e.g. insert A:5, insert B:3 (B swims, swap(1, 0) leaves B→1 in the map), then changePriority(B, 9) changes A, which is now in slot 1
  • +0.5(b) O(log n) with the map (O(1) expected lookup, then one swim or sink); O(n) without it, because finding the item is a scan
  • +0.75(c) Its children were ≥ the old priority, which is ≥ the new one, so the order below it still holds; only the edge to its parent can break
  • −0.125The sequence in (a) depends on which index the student's swap updates and gets it backwards, but the idea is right

(a) insert A:5 → slot 0, map A→0. insert B:3 → slot 1, then B swims with swap(1, 0). Now heap is B, A. The broken swap updates only heap[1].item = A→1, so the map still says B→1. changePriority(B, 9) looks up slot 1 and changes A. (If the swap is called as swap(0, 1) it updates B and leaves A wrong instead: either way one item points at the other's slot.)

(b) O(log n) vs O(n). (c) Before the change, each child ≥ old priority. The new priority is smaller, so each child is still ≥ it. Only the parent can now be larger.

  • +0.25Throws IllegalArgumentException for null
  • +0.5Grows when size == heap.length (e.g. Arrays.copyOf(heap, 2 * heap.length)), before writing
  • +0.5Places x at index size, increments size, and swims from the new last index
  • +0.75swim loops while i > 0 (the root has no parent)
  • +0.75Continues only while the node is smaller than its parent: compare(heap[i], heap[parent(i)]) < 0
  • +0.75Swaps with the parent and moves up: i = parent(i)
  • +0.5Stops as soon as the node is not smaller than its parent (no extra swaps)
  • −0.5Compare is backwards (swims while the node is larger): a coherent max-heap swim. Award the items in mirror image, then apply this
  • −0.125Minor logic or major syntax errors showing lack of understanding
public void insert(T x) {
  if (x == null) throw new IllegalArgumentException();
  if (size == heap.length) heap = Arrays.copyOf(heap, 2 * heap.length);  // full: grow
  heap[size] = x;
  size++;
  swim(size - 1);
}

private void swim(int i) {
  while (i > 0 && compare(heap[i], heap[parent(i)]) < 0) {  // smaller than my parent
    swap(i, parent(i));
    i = parent(i);
  }
}

Say the loop as a sentence first: "while I'm not the root and I'm smaller than my parent, swap up." Translate compare(a, b) < 0 as a < b.

Implement put for the course's separate-chaining HashMap. If the key is already there, replace its value and return the old value. Otherwise add it at the head of its bucket and return null. After adding a new key, call rehash() if the load factor size / buckets.length is now above 0.75. Null keys or values throw IllegalArgumentException.

Rubric and reference solution

4 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.25Throws IllegalArgumentException for a null key or value
  • +0.5Finds the bucket with Math.floorMod(key.hashCode(), buckets.length)
  • +0.5Walks that bucket's chain until null
  • +1On an equals match: saves the old value, replaces it, returns the old value (size unchanged)
  • +0.75Otherwise inserts a new node at the head: node.next = buckets[i]; buckets[i] = node;
  • +0.25Increments size only for a new key
  • +0.5Checks the load factor with real division after adding, and calls rehash()
  • +0.25Returns null for a new key
  • −0.25Integer division size / buckets.length, which is 0 until the table is full, so it never rehashes in time
  • −0.25Compares keys with ==
  • −0.25Uses % without floorMod
  • −0.125Minor logic or major syntax errors showing lack of understanding
public V put(K key, V value) {
  if (key == null || value == null) throw new IllegalArgumentException();
  int i = Math.floorMod(key.hashCode(), buckets.length);
  for (Node<K, V> curr = buckets[i]; curr != null; curr = curr.next) {
    if (curr.key.equals(key)) {          // key exists: replace
      V old = curr.value;
      curr.value = value;
      return old;
    }
  }
  Node<K, V> node = new Node<>(key, value);
  node.next = buckets[i];                // new node goes at the head: O(1)
  buckets[i] = node;
  size++;
  if ((double) size / buckets.length > 0.75) rehash();   // double, not int, division
  return null;
}

  • +0.5find starts at indexFor(key)
  • +0.5find loops until it reaches an empty (null) slot
  • +1find keeps going past tombstones (and past other keys): only null ends the search
  • +0.5Checks deleted before comparing keys, so a tombstone never matches
  • +0.75Steps with wraparound: i = (i + 1) % slots.length
  • +0.25Returns -1 after the loop
  • +0.5containsKey throws for null and returns find(key) != -1
  • +0.25remove returns null when find gives -1
  • +0.75remove marks the entry deleted (a tombstone), it does not set the slot to null
  • +0.5remove decrements size and leaves used alone
  • +0.5remove returns the removed value (saved before or after marking)
  • −0.5remove decrements used (the slot is still not null, so used must stay)
  • −0.25Compares keys with ==
  • −0.5Steps with % size or any length other than slots.length
  • −0.125Minor logic or major syntax errors showing lack of understanding
private int find(K key) {
  int i = indexFor(key);
  while (slots[i] != null) {                 // only an empty slot ends the search
    if (!slots[i].deleted && slots[i].key.equals(key)) return i;
    i = (i + 1) % slots.length;              // tombstone or other key: keep going
  }
  return -1;
}

public boolean containsKey(K key) {
  if (key == null) throw new IllegalArgumentException();
  return find(key) != -1;
}

public V remove(K key) {
  if (key == null) throw new IllegalArgumentException();
  int i = find(key);
  if (i == -1) return null;
  V old = slots[i].value;
  slots[i].deleted = true;                   // tombstone, NOT null
  size--;                                    // used stays the same
  return old;
}

Setting the slot to null would cut the probe path: any key stored past it becomes unreachable. That is the whole reason tombstones exist. The loop always ends because the rehash rule keeps used ≤ m/2, so there is always a null slot.

Write the value iterator for the open-addressing map. It visits slots 0, 1, 2, … and returns the value of every live entry, skipping empty slots and tombstones. Use O(1) extra space. hasNext must not change what next will return. next() throws NoSuchElementException when no values are left.

4 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Keeps a single slot index as the field (the slot the next value comes from)
  • +1Skipping moves past slots that are null or tombstones, and stops at slots.length
  • +0.5The constructor skips to the first live entry
  • +0.5hasNext returns i < slots.length (or an equivalent that has no side effect)
  • +0.75next returns that slot's value (not the Entry, not the key)
  • +0.5next then moves to the following live entry
  • +0.25next throws NoSuchElementException when no values are left
  • −0.5Copies the values into a list or array first (O(n) space). Grade the items for that approach, then apply this
  • −0.5hasNext advances the index, so calling it twice skips a value
  • −0.125Minor logic or major syntax errors showing lack of understanding
private class ValueIterator implements Iterator<V> {
  private int i;                         // the slot next() returns from

  ValueIterator() {
    skip();                              // land on the first live entry
  }

  private void skip() {                  // move past empty slots AND tombstones
    while (i < slots.length && (slots[i] == null || slots[i].deleted)) i++;
  }

  @Override
  public boolean hasNext() {
    return i < slots.length;
  }

  @Override
  public V next() {
    if (!hasNext()) throw new NoSuchElementException();
    V value = slots[i].value;
    i++;
    skip();
    return value;
  }
}

  • +0.25Throws IllegalArgumentException for null
  • +0.5Finds the slot with index.get(item)
  • +0.5Throws NoSuchElementException when the item isn't in the map
  • +0.75Swaps the item with the last entry (size - 1)
  • +0.75Removes the item from the index map
  • +0.5Clears the last slot and decrements size
  • +0.5Only repairs order when the removed slot is still inside the heap (i < size)
  • +1.25Calls both swim(i) and sink(i): the filler from the bottom can be too small for its new parent or too large for its new children. Award 0.5 for only one of them
  • −1Finds the item by scanning the heap array (O(n)) instead of using the map
  • −0.125Minor logic or major syntax errors showing lack of understanding
public void remove(T item) {
  if (item == null) throw new IllegalArgumentException();
  Integer i = index.get(item);
  if (i == null) throw new NoSuchElementException();
  swap(i, size - 1);              // item moves to the last slot; swap updates the map
  index.remove(item);             // item is gone from the map...
  heap[size - 1] = null;          // ...and from the array
  size--;
  if (i < size) {                 // a filler from the bottom now sits at i:
    swim(i);                      //   it may be smaller than its new parent
    sink(i);                      //   or larger than its new children
  }
}

Why both: the last entry came from a different branch of the tree. Example priorities 1, 50, 2, 60, 90, 3, 6 (array order): removing 90 at slot 4 moves 6 there, and 6 is smaller than its new parent 50, so it has to swim. Removing an item near the top usually needs sink instead.

3 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Takes pivot = a[lo]
  • +0.5Starts the boundary at lo (the end of the < region)
  • +0.5Scans j from lo + 1 through hi inclusive
  • +0.75When a[j] < pivot: grows the boundary and swaps a[j] into it
  • +0.5After the loop, swaps the pivot from lo into the boundary slot
  • +0.25Returns the pivot's final index
  • −0.5Partitions around a[hi] instead of a[lo], which is not what was asked
  • −0.125Minor logic or major syntax errors showing lack of understanding
private static int partition(int[] a, int lo, int hi) {
  int pivot = a[lo];
  int i = lo;                          // a[lo+1..i] < pivot
  for (int j = lo + 1; j <= hi; j++) { // a[i+1..j-1] >= pivot
    if (a[j] < pivot) {
      i++;
      swap(a, i, j);
    }
  }
  swap(a, lo, i);                      // pivot goes between the two regions
  return i;
}

Mirror of the course's Lomuto: the pivot sits at the left end, so the boundary starts on it and is incremented before each swap. Trace [4, 7, 1, 9, 2]: after the loop it is [4, 1, 2, 9, 7] with boundary 2, then the final swap gives [2, 1, 4, 9, 7] and returns 2.

Return a shortest path (fewest edges) from start to target in an undirected graph, as a list of vertices from start to target inclusive. If start equals target, return a list holding just start. If target can't be reached, return an empty list. Each vertex may enter your waiting structure at most once, and the graph must not be modified.

Rubric and reference solution

5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Creates a queue and enqueues start
  • +0.5Keeps a parent (or came-from) map; start is in it, which marks it visited
  • +0.5Loops while the queue is not empty, dequeuing from the front
  • +0.5Iterates over g.neighbors(v)
  • +0.75Before enqueueing a neighbor: checks it is unvisited, records its parent, marks it visited
  • +0.5Returns an empty list when target was never reached
  • +1Builds the path by walking parent links back from target to start
  • +0.5Reverses it so the list starts at start
  • +0.25start == target gives a one-element list
  • −1Uses a stack or recursion instead of a queue: DFS does not give the fewest edges
  • −0.5Modifies the graph
  • −0.125Minor logic or major syntax errors showing lack of understanding
public static <V> List<V> shortestPath(Graph<V> g, V start, V target) {
  Map<V, V> parent = new HashMap<>();       // also the visited set
  Queue<V> queue = new ArrayDeque<>();
  parent.put(start, null);                  // start has no parent
  queue.add(start);
  while (!queue.isEmpty()) {
    V v = queue.remove();
    if (v.equals(target)) break;            // first time we reach it is by a shortest path
    for (V w : g.neighbors(v)) {
      if (!parent.containsKey(w)) {         // check AND mark before enqueueing
        parent.put(w, v);
        queue.add(w);
      }
    }
  }
  List<V> path = new ArrayList<>();
  if (!parent.containsKey(target)) return path;   // unreachable: empty list
  for (V v = target; v != null; v = parent.get(v)) path.add(v);   // walk back
  Collections.reverse(path);                // start first
  return path;
}

Stopping as soon as target is dequeued is optional. BFS reaches every vertex for the first time by a shortest route, so the parent links form shortest paths either way.
