  • +0.5(a) 0:22, 1:33, 2:1, 3:13, 4:2
  • +0.5(a) Slots examined: 22 → 1, 33 → 2, 1 → 2, 13 → 2, 2 → 3
  • +0.75(b) 44 hashes to 0: examines 0, 1, 2, 3, 4, 5 (empty) = 6 slots, returns null
  • +0.75(c) Primary clustering: occupied slots form one run, and any key hashing anywhere into the run must probe to its end, which makes the run longer still

33 % 11 = 0 → 0 taken, 1              (2)

13 % 11 = 2 → 2 taken, 3              (2)

(c) Slots 0–4 are one cluster. 1 and 13 never collided with their own home keys; they collided with keys that spilled over from slot 0. Every key that lands in the cluster extends it.

Rubric and reference solution

5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.5Keeps a reference to the old array
  • +0.5Allocates the new array (e.g. (Entry<K, V>[]) new Entry[newCapacity]) and assigns it to slots before reinserting
  • +0.5Visits every old slot
  • +0.75Skips null slots and tombstones
  • +0.75Computes each home slot with the new length (indexFor after slots is replaced)
  • +0.75Probes forward with wraparound (i + 1) % slots.length to the first null slot
  • +0.5Stores the entry there (reusing it is fine)
  • +0.75Sets used = size and leaves size unchanged
  • −0.5Copies tombstones into the new table
  • −0.5Indexes with the old length
  • −0.25Calls put
  • −0.125Minor logic or major syntax errors showing lack of understanding
@SuppressWarnings("unchecked")
private void rehash(int newCapacity) {
  Entry<K, V>[] old = slots;
  slots = (Entry<K, V>[]) new Entry[newCapacity];   // indexFor now uses the new length
  for (int j = 0; j < old.length; j++) {
    Entry<K, V> e = old[j];
    if (e == null || e.deleted) continue;           // tombstones are dropped
    int i = indexFor(e.key);
    while (slots[i] != null) {                      // new table has no tombstones:
      i = (i + 1) % slots.length;                   // just find the first empty slot
    }
    slots[i] = e;                                   // reuse the entry object
  }
  used = size;                                      // no tombstones left; size unchanged
}

The new table has no tombstones and no duplicate keys, so the probe only has to find the first empty slot: no equals checks needed. After the rehash every non-null slot is live, which is why used becomes size.

@SuppressWarnings("unchecked")
private void rehash() {
  Node<K, V>[] old = buckets;
  int capacity = (primeIndex + 1 < PRIMES.length)
      ? PRIMES[++primeIndex]
      : 2 * old.length + 1;
  buckets = (Node<K, V>[]) new Node[capacity];   // indexFor now uses the new length
  for (int b = 0; b < old.length; b++) {
    Node<K, V> curr = old[b];
    while (curr != null) {
      Node<K, V> next = curr.next;               // save it: relinking overwrites curr.next
      int i = indexFor(curr.key);
      curr.next = buckets[i];                    // insert at the head of the new bucket
      buckets[i] = curr;
      curr = next;
    }
  }                                              // size is unchanged: same nodes, new places
}

Two classic bugs: using PRIMES[primeIndex++] (that's the current size), and setting buckets[i] = curr without curr.next = buckets[i] (the node drags its old chain along).

Implement in-place heapsort: sort a into ascending order using O(1) extra space and O(n log n) time. Write the helper sink(a, i, n) for a max-heap stored in a[0..n-1] (children of i at 2i + 1 and 2i + 2), then heapSort using it.

Rubric and reference solution

4 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.25sink loops while i has a child: 2 * i + 1 < n (bounded by n, not a.length)
  • +0.5sink picks the larger child, checking the right child exists
  • +0.5sink stops when a[i] is at least that child, otherwise swaps and continues from the child
  • +0.75Builds the max-heap bottom-up: sink from n / 2 - 1 down to 0
  • +0.5Loops end from n - 1 down to 1
  • +0.75Swaps a[0] (the max) with a[end]
  • +0.75Then sinks the root within the shrunk heap: sink(a, 0, end)
  • −0.5Uses a min-heap, or a second array or PriorityQueue (not in place)
  • −0.5Sinks with the full length after each swap, pulling sorted values back into the heap
  • −0.125Minor logic or major syntax errors showing lack of understanding
// Max-heap in a[0..n-1]: moves a[i] down until it is >= both children.
private static void sink(int[] a, int i, int n) {
  while (2 * i + 1 < n) {
    int b = 2 * i + 1;                     // left child
    if (b + 1 < n && a[b + 1] > a[b]) b++; // the larger child
    if (a[i] >= a[b]) break;
    int t = a[i]; a[i] = a[b]; a[b] = t;
    i = b;
  }
}

public static void heapSort(int[] a) {
  int n = a.length;
  for (int i = n / 2 - 1; i >= 0; i--) {   // 1. heapify bottom-up: O(n)
    sink(a, i, n);
  }
  for (int end = n - 1; end > 0; end--) {  // 2. move the max to the end, shrink the heap
    int t = a[0]; a[0] = a[end]; a[end] = t;
    sink(a, 0, end);                       // heap is now a[0..end-1]
  }
}

After each swap, a[end..n-1] is sorted and must stay out of the heap, which is why sink takes the heap size as a parameter.

private void swap(int i, int j) {
  Entry<T> t = heap[i]; heap[i] = heap[j]; heap[j] = t;
  where.put(heap[i].item, i);              // both moved entries get their new index
  where.put(heap[j].item, j);
}

public void changePriority(T item, int priority) {
  Integer i = where.get(item);             // O(1): no searching the heap
  if (i == null) throw new IllegalArgumentException();
  int old = heap[i].priority;
  heap[i].priority = priority;
  if (priority < old) swim(i);             // smaller is better in a min-heap: move up
  else sink(i);                            // larger: move down
}

The map is only correct if every move goes through swap, and swap moves two items, so both need new map entries. In a min-heap a smaller priority can only break the order with the parent (swim); a larger one only with the children (sink).

Throw IllegalArgumentException if a is null or k is negative.

Rubric and reference solution

5 pts. Start from 0 and add each item the answer earns; penalties come off at the end.

  • +0.25Throws IllegalArgumentException for null or negative k
  • +1Counts with a HashMap, e.g. count.put(x, count.getOrDefault(x, 0) + 1)
  • +0.75PriorityQueue entries carry both the value and its count (e.g. int[]{value, count} or Map.Entry)
  • +0.75Orders the queue by count, least frequent at the root (min-heap by count)
  • +1Adds while fewer than k entries; once full, replaces the root only when the new count is larger
  • +0.5Handles k = 0 without crashing
  • +0.75Returns the values (not the counts) of what is left in the queue
  • −1Puts all d entries in the queue, or sorts all the counts
  • −0.5Orders by value instead of count
  • −0.125Minor logic or major syntax errors showing lack of understanding
public static List<Integer> topKFrequent(int[] a, int k) {
  if (a == null || k < 0) throw new IllegalArgumentException();
  Map<Integer, Integer> count = new HashMap<>();            // 1. count: O(n) expected
  for (int x : a) {
    count.put(x, count.getOrDefault(x, 0) + 1);
  }
  // 2. MIN-heap by count of {value, count}: root = least frequent of the kept k
  PriorityQueue<int[]> pq = new PriorityQueue<>((p, q) -> Integer.compare(p[1], q[1]));
  for (Map.Entry<Integer, Integer> e : count.entrySet()) {
    int[] pair = {e.getKey(), e.getValue()};
    if (pq.size() < k) {
      pq.add(pair);
    } else if (k > 0 && pair[1] > pq.peek()[1]) {           // more frequent than the weakest kept
      pq.remove();
      pq.add(pair);
    }
  }
  List<Integer> out = new ArrayList<>();
  for (int[] pair : pq) out.add(pair[0]);                   // any order is fine
  return out;
}

Hashing plus a heap: the map turns n values into d (value, count) pairs in O(n), then it's top k on the counts. Keeping the k most frequent means the one to throw out next is the least frequent kept, so it sits at the root of a min-heap.
